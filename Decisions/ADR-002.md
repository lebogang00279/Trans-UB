# ADR-002 — Depend on Ports for Persistence and Notification

**Status:** Accepted  
**Related:** UC-05; modular layered monolith

## Context
Reservation must coordinate persistence and notification while preserving transaction integrity. Notification failure must not corrupt a valid reservation.

## Options
1. Core logic depends directly on concrete database/notification classes.
2. Core logic depends on stable interfaces/ports with adapters.
3. Introduce microservices/event broker.

## Decision
Choose **Option 2**.

`ReservationService` depends on repository ports and `NotificationPort`, injected through constructors.

## Positive consequences
- clear dependency direction;
- improved testability;
- technology changes are localized;
- notification failure is isolated from core state.

## Negative consequences
- more interfaces/adapters;
- wiring must be maintained.

## Rejected option
Microservices/event broker are rejected because they add unnecessary distributed-system complexity for the current prototype.
